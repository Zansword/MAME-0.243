# MAME 0.243 Atomiswave/PowerVR2 (Metal Slug 6) Emulation Profiling & Fix Report

> **한 줄 요약**: MAME 0.243의 Sammy Atomiswave(Dreamcast 파생 하드웨어) PowerVR2 비디오 코어를 flycast / Demul 소스와 교차 분석하여, 프레임 저하·오디오 끊김·그래픽 오류의 근본 원인을 규명하고 실제 패치를 적용해본 리버스 엔지니어링/디버깅 기록입니다.

**컴파일러**: mingw-mame-20100102

---

## 1. 배경 및 목표

- **대상**: `mame_243/src/mame/video/powervr2.cpp` (+`.h`) — Sammy Atomiswave 기판(SH-4 200MHz + PowerVR2 100MHz + Yamaha AICA/ARM7) 드라이버의 비디오 코어.
- **테스트 타이틀**: *Metal Slug 6* (`mslug6`) — 이름과 달리 Neo Geo가 아니라 Atomiswave(드림캐스트 파생) 하드웨어입니다.
- **증상**: BIOS 부팅 화면은 100% 속도가 나오지만, 실제 게임플레이 렌더링이 시작되면 70%대로 저하. 특정 화면(랭킹 화면 등)에서 그래픽이 잘못 표시되고, 사운드가 프레임 저하와 함께 끊김.
- **비교 기준**: 동일 하드웨어를 에뮬레이션하는 **flycast**(현행 활발히 유지보수되는 고정확도 에뮬레이터)와 **Demul**(2006년대 초기 세대, PSEmu Pro 스타일 플러그인 아키텍처)의 소스를 함께 확보하여 3자 비교 분석을 진행했습니다.

## 2. 방법론

1. mame_243(MAME 0.243) 소스에서 성능/정확도 이슈가 의심되는 코드를 정적 분석으로 특정.
2. flycast / Demul의 동일 하드웨어 구현을 찾아 구조적으로 대조.
3. 차이가 확인되면 **가설 → 최소 침습 패치 → (가능한 경우) 검증 → 문제 시 롤백** 순으로 진행.
4. 검증 불가능한 상태(실제 빌드/런타임 접근 제한)에서 리스크가 큰 변경(스레딩 등)은 **실패 시 즉시 되돌리고 교훈을 기록**.

## 3. 핵심 아키텍처 결론

### 3.1 세 에뮬레이터의 근본적 구조 차이

| | MAME (mame_243, 수정 전) | flycast | Demul |
|---|---|---|---|
| 폴리곤 래스터/텍스처/블렌드 | CPU 스칼라 루프 (소프트웨어 렌더러) | **실제 GPU 하드웨어** (OpenGL/Vulkan/DX 드로우콜) | **실제 GPU 하드웨어** (OpenGL) |
| SH4 CPU 실행 | 메인 협조적 스케줄러 스레드 공유 | 전용 OS 스레드 분리 (`ThreadedRendering`) | 코어 구조상 CPU/디바이스 분리 |
| GPU 렌더 요청 처리 | 레지스터 write 즉시 그 자리에서 동기 계산 | TA_context 스냅샷 → 별도 렌더 스레드 큐잉(fire-and-forget) | GPU 플러그인 DLL 경계로 물리적 분리 |
| 오디오 생성 | 메인 스케줄러의 주기 타이머(`sound_manager::update`)에 종속 | 별도 스레드/버퍼 경로 | **전용 실시간 우선순위 스레드**(`THREAD_PRIORITY_TIME_CRITICAL`), DirectSound 하드웨어 알림 이벤트로 구동 |

**결론**: MAME은 SH4·GPU(PowerVR2)·사운드(AICA/ARM7)를 **하나의 협조적 단일 스레드**가 시분할로 처리하는 구조라서, 실제로 독립된 병렬 실리콘(드림캐스트/나오미급 하드웨어)의 타이밍을 재현하는 데 구조적 제약이 있습니다. flycast·Demul은 **애초부터 GPU/오디오를 별도 스레드·별도 하드웨어(GPU API)로 분리**하도록 설계되어 이 문제에서 자유롭습니다.

> 다만 이는 "PS1 이후 아케이드 기판 전부"의 문제가 아니라, **PowerVR2+AICA/ARM7처럼 진짜 병렬 실리콘으로 동작하는 특정 세대 하드웨어**에 국한된 제약입니다. MAME은 다른 다중 CPU 아케이드 기판들은 이미 정확하게 구현하고 있습니다.

### 3.2 리스크 등급으로 본 "미구현/미완성" 항목 분류

| 등급 | 항목 | 비고 |
|---|---|---|
| 낮음 (로컬 코드, MAME 코어 무관) | 더티 리전, SIMD 블렌드, 레이어 순서, 레지스터 누락, G2 DMA 벌크 복사, RTT, 모디파이어 볼륨 | 이번에 실제로 구현/수정함 |
| 중간 (MAME 제공 도구 재조합, 동시성 버그 가능) | `osd_work_queue` 기반 비동기 렌더 워커 | 성공 사례와 실패(롤백) 사례 모두 존재 |
| 높음 (MAME 코어/뼈대 자체를 수정해야 함) | 사운드 파이프라인 전체 스레드 분리, GPU 하드웨어 드로우콜 기반 렌더러 전환 | 미착수 — 전체 드라이버에 영향을 주는 대수술 필요 |

## 4. 발견 및 수정한 이슈 목록

### 4.1 프레임 저하 (성능)

1. **완전 동기식 렌더링** — `STARTRENDER` 레지스터 write 시점에 SH4 명령 디스패치 콜스택 안에서 직접 전체 화면을 재계산 → `osd_work_queue` 기반 비동기 워커로 분리 (flycast의 `Renderer_if.cpp` 패턴을 참고, `epic12.cpp`의 기존 MAME 관례를 재사용).
2. **레지스터 스냅샷 누락으로 인한 픽셀 오염** — 비동기화 도중 SH4가 `region_base`/`param_base` 등을 덮어써서 워커가 엉뚱한 좌표를 읽던 실제 레이스 컨디션 발견 및 수정 (`receiveddata`에 `*_snap` 필드 추가).
3. **풀스크린 재계산 낭비** — 매 렌더마다 1024x1024 전체를 지우고 다시 채우던 것을, 리전 리스트의 타일 좌표에서 계산한 **더티 리전 바운딩 박스**만 처리하도록 축소.
4. **프레임버퍼 변환 픽셀 단위 `address_space` 디스패치** — `fb_convert_*` 20개 함수의 `space.write_word/byte/dword` 호출을 VRAM 포인터 직접 접근으로 교체.
5. **G2 DMA(사운드 샘플 로드용) 2바이트 단위 전송** — 내레이션 음성 재생 시 병목의 원인. dword 단위 벌크 복사 고속 경로 추가 (동작 100% 동일, 디스패치 횟수만 절반).
6. **EOR(렌더 완료) IRQ 타이밍** — 타일 개수 기반 매직넘버 → flycast와 동일한 실제 데이터량 비례 공식으로 교체.
7. **사운드 끊김의 근본 원인** — `sound_manager::update()`가 렌더 워커와 **같은 스레드**를 공유해서, 블로킹 대기가 오디오까지 지연시킴을 확인. 화면 표시 경로(`screen_update`)만 논블로킹 폴링으로 전환하여 완화.
8. **밴드 병렬 래스터라이즈 시도 → 롤백**: 다중 코어를 더 쓰기 위해 화면을 여러 밴드로 나눠 병렬 처리하는 시도를 했으나, 실제 테스트에서 그래픽이 더 불안정해짐(`osd_work_queue`의 멀티스레드 "도와주기" 경로 관련 추정) — **실증 없이 동시성 코드를 밀어붙이지 않는다**는 원칙에 따라 즉시 원복.
9. **블렌드 연산 SIMD화** — 수작업 32비트 SWAR 비트 트릭 6개 함수를 MAME 내장 `rgbaint_t`(SSE2/AltiVec/제네릭 자동 선택) 기반으로 재작성.

### 4.2 그래픽 정확도

10. **레이어 그리기 순서 버그** — Opaque → **Translucent → Punch-Through** (오류) 순서였던 것을, flycast의 실제 렌더 패스(Opaque → **Punch-Through → Translucent**)에 맞춰 수정.
11. **Render-to-Texture(RTT) 완전 미구현** — `FB_W_SOF1`의 24번 비트(RTT 신호)를 어디서도 처리하지 않아, 텍스처로 사전 렌더링되는 UI(랭킹 화면 등)가 깨지고, 마스킹 안 된 비트로 인해 **16MB+ 범위 밖 메모리 접근** 버그까지 발생. RTT 감지 + 마스킹 + 텍스처 메모리로의 렌더 타겟 리다이렉트 구현.
12. **`Y_COEFF` 레지스터(0x118) 완전 누락** — 실제 로그 분석(unmapped write)으로 발견. flycast 대조 후 실제 RW 레지스터로 확인, 저장소+핸들러+레지스터맵 등록 추가.
13. **모디파이어 볼륨(그림자/조명 스텐실 효과) 구현** — MAME과 Demul 둘 다 미구현(Demul은 디버그 로그조차 안 남기고 폐기)이었던 기능을 flycast의 스텐실 볼륨 알고리즘을 참고해 CPU 소프트웨어 버전(단순화된 홀짝 카운팅 규칙)으로 신규 구현. TA 파서가 데이터 자체를 버리고 있던 숨은 버그도 함께 발견/수정.

## 5. 아직 남은 문제

- 랭킹 화면 등 일부 화면의 근본 원인은 **미해결** — 레이어 순서, 더티 리전, RTT, Y_COEFF를 순차적으로 배제했으나 확정 짓지 못함. 실제 런타임 레지스터/TA 커맨드 트레이스가 필요한 단계.
- 적군이 많은 오버드로우 집중 구간의 프레임 저하는 **CPU 소프트웨어 렌더러의 물리적 한계**로 판단 — GPU 오프로드 없이는 근본 해결 불가.
- 모디파이어 볼륨 구현은 의도적으로 단순화됨(다중 볼륨 조합·폴리곤별 Shadow 비트 게이팅 미지원).

## 6. 사용한 도구/방법에 대한 메모

- 실제 빌드·런타임 디버깅 환경이 제한적이어서, 모든 변경은 **정적 코드 분석 + 3자 소스 교차 검증(MAME/flycast/Demul)**으로 근거를 확보한 뒤 최소 침습적으로 적용.
- 검증 불가능한 리스크(스레딩 동시성)는 실제 사용자 테스트 결과가 나쁘면 **주저 없이 롤백**하고 교훈을 기록 — "고쳐질 것 같다"는 추측만으로 위험한 변경을 밀어붙이지 않음.
- 사용자가 제공한 실제 MAME 언맵(unmapped access) 로그를 근거로 삼아 추측이 아닌 **관찰된 사실 기반**으로 레지스터 누락을 확정.

---

## 7. 라이선스 및 사용 소스 주의사항

- 본 저장소의 MAME/flycast 관련 수정 코드는 각 원본 프로젝트의 라이선스(GPL-2.0-or-later 등)를 따릅니다.
- **Demul 소스코드는 본 저장소에 포함되어 있지 않습니다.** Demul의 원본 배포 라이선스 문구가 표준 오픈소스 라이선스와 다른 비표준/제한적 문구를 포함하고 있어(재배포 불가 명시), 분석 결과만 텍스트로 인용했습니다.
- 게임 ROM 파일은 포함되어 있지 않습니다.

## 8. 요약 한 줄 결론

> MAME의 협조적 단일 스레드 스케줄러 구조는, GPU와 사운드 CPU가 진짜 독립 병렬 실리콘으로 동작하는 드림캐스트/나오미급 하드웨어(SH4 + PowerVR2 + AICA/ARM7)를 타이밍 정확하게 재현하는 데 구조적 제약이 된다. 부분적 완화(비동기 워커 스레드, 타이밍 보정, 논블로킹 폴링)는 가능하지만, 완전한 해결에는 MAME의 핵심 스케줄러·사운드 파이프라인 수준의 대수술이 필요하다. 반면 flycast·Demul처럼 애초에 CPU·GPU·오디오를 독립 스레드 및 실제 GPU 하드웨어로 설계한 에뮬레이터는 이 구조적 문제에서 자유롭다.<img width="406" height="307" alt="화면 캡처 2026-09-24 225020" src="https://github.com/user-attachments/assets/a5692ec8-274b-436c-a589-7d87fc2fc5bb" />
원래대로라면, 랭킹 화면이 나와있어야할 메뉴가 미구현된 부분이 남아있다.
